- [Qwen/Qwen3.8-2.4T-A95B](https://huggingface.co/Qwen/Qwen3.8-2.4T-A95B) — 阿里新发 MoE 巨模型（A95B 激活），工具调用与 Agent 能力是本轮重点。
- [Lightricks/LTX-2.5](https://huggingface.co/Lightricks/LTX-2.5) — 视频生成模型更新，57k 下载当日入榜，视频 Agent 的输入源之一。
- [multimodalart/minimax-h3 Space](https://huggingface.co/spaces/multimodalart/minimax-h3) — 社区 Space：MiniMax H3 文生视频 + 同步配乐，展示「模型即 Agent 工具」的多模态工作流。
- [OpenART](https://huggingface.co/papers/2608.00677) — 用开放式环境演化扩展 Agent 红队测试（182 赞当日热门），把「让 Agent 更安全」做成可扩展评测。
- [ToolHazard](https://huggingface.co/papers/2608.11878) — 北大：为 LLM Agent 构建对抗环境做安全评测与对齐，Agent 上线前的红队基准。
- [SkillZip](https://huggingface.co/papers/2608.05604) — 保契约的图压缩，让 Agent 技能库可扩展到大规模而不丢能力边界。

## 【arXiv 精选】

- [EvoGraph-Mem](https://arxiv.org/abs/2608.11248) — 故障感知、可编辑的图记忆，给长期语言 Agent 用；记忆不再是只增不减的黑盒。
- [Total Recall at What Cost?](https://arxiv.org/abs/2608.11879) — 基准测试 Agent 记忆系统的服务成本（cs.CL），直击「全量记忆召回」的算力账。
- [Retry, Switch, or Abstain?](https://arxiv.org/abs/2608.11977) — 通过可控错误注入学「策略感知的工具使用策略」，给工具调用加了 retry/switch/abstain 三档开关。
- [VAKRA](https://arxiv.org/abs/2608.12282) — 在工具使用策略下评估跨 API 与检索的多跳推理，把工具调用与推理控制绑成统一基准。
- [The Sleeping Agent](https://arxiv.org/abs/2608.11775) — 探究要点式上下文压缩在 Agent 中丢失了什么（memory/context），给 CLAUDE.md 式长上下文敲警钟。
- [Agent Skills Can Be Harmful](https://arxiv.org/abs/2608.11888) — 实证研究 LLM Agent 中「技能」引发的故障危害，配 SkillZip 形成「技能能放大也能坑」的安全视角。
- [Diagnosis Before Recovery](https://arxiv.org/abs/2608.11772) — 把 Agent 失败转化为选择性自我纠正（cs.CL），先诊断再恢复而非盲目重试。
- [Harness-IF](https://arxiv.org/abs/2608.11727) — 评估 Coding Agent 跨指令界面（CLAUDE.md / 系统提示 / 工具描述）的指令遵循能力，呼应「调教 AI」工程实践。

## 今日值得深入

1. **DeepSeek Harness (dsh)** —— 一个用 TypeScript strict 全开、pnpm workspace、100% 测试门禁写出来的「一切皆插件」Agent 运行时。它把模型/工具/技能/会话/沙箱全做成可替换插件，正好对应 vuji 正在做的 RouterClient / ToolExecutor / 三层路由思路。建议对照 [cnblogs 深度分析](https://www.cnblogs.com/isLinXu/p/22457058) 读它的 Cordis 插件框架与能力缝隙设计，思考自己的 WorkMusic/AllergyBaby 能否复用这套「插件即能力」范式。
2. **12-factor-agents** —— [humanlayer/12-factor-agents](https://github.com/humanlayer/12-factor-agents) 提出的「确定性代码控制流程、LLM 只做工具调用转换」原则，与 vuji 的「Prompt 管意图、Code 管行为」洞察完全一致。前端转 Agent 最该先吃透这 12 条，再决定用哪个框架。
