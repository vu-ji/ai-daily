## 【arXiv 精选】

- [MidTool: Mid-training Data Synthesis for Agentic Tool Use](https://arxiv.org/abs/2608.20314) — 把「通用工具调用」当成需要专门 mid-training 的能力：用真实工具 API + MCP skills + 文档工作流合成监督语料，教模型识别工具可用性、从上下文取参、组合调用链、信息不全时恢复；Qwen3-4B/8B 在 BFCL、τ²-Bench、MCP Universe 上 SFT 与 RL 双双提升。
- [One Success Isn't Reliability: Thinkingbox, a Sandbox and Benchmark for Agents in Stateful Business Workflows](https://arxiv.org/abs/2608.19741) — 微软放出 MCP 兼容沙箱 + 507 条带策略约束的有状态业务流程（零售/保险/银行 IT/HR），最强模型 pass@1 65.36% 但 pass^20 只有 25.25%，且大量失败案例「干净退出且工具调用合法」——证明响应级/工具级信号根本不能代理端到端完成度。
- [Beyond Memory Majority: Latent-Source Reasoning for Multi-Agent Memory Arbitration](https://arxiv.org/abs/2608.19701) — 指出多智能体记忆的隐性失效「记忆相关性偏差」：不同 Agent 写的记忆若继承同一上游来源，投票时会被重复计数造出虚假多数；CAMA 用依赖推断 + 溯源符号先验估计「有效独立证据数」，并学一个按需回溯上游的检索策略。
- [Hierarchical Self-Improvement: A Framework for Task-Specific Evolvable Agent Harnesses](https://arxiv.org/abs/2608.08466) — 把 harness 从「部署后固定的脚手架」改成按任务族热插拔、可被自身重写的对象：冻结 LLM 同时充当执行者/进化器/元进化器；BALROG 上 BabyAI +39.3、Crafter +33.0，但在超出底座能力的 NLE 上零提升，明确给出「反馈保真度」与「底座能力」两条上界。
- [Inducing Task Models from Computer-Use Traces](https://arxiv.org/abs/2608.20319) — 从被动录制的截图 + 键鼠事件里反推出可审计、可复用的任务模型：先把交织的多线程活动拆成隐任务（与人工分组一致性 0.974），再为每个任务生成「目标层级 + 控制流」双模型，据此提炼的技能让留出任务准确率 +30.0%。
- [FlowEvo: Self-Evolving Agents through the Co-Evolution of Workflows and Executable Skills](https://arxiv.org/abs/2607.21596) — 免训练框架：把跑通的 workflow 编译成可调用技能存进持久技能库，并跟踪每个技能的下游效用、主动抑制负迁移；共享 GPT-4o-mini 底座下 ALFWorld 达 85.6%（超最强基线 26.4 分）且 token 只用约三分之一，10 个 7B–671B 底座上 49/50 组胜过 ExpeL。
- [SkillEvo: Self-Renewing Evolution Gradients from Multi-Turn Interaction Feedback](https://arxiv.org/abs/2608.13120) — 诊断出技能自进化「第一轮后梯度就衰减」的根因是反馈只来自单轮 QA；改用多轮用户模拟当「反馈发生器」层层暴露缺陷，再加一层主动修复事实退化与结构膨胀的治理层；9 个生产技能、98 个技能文件上比自反思进化高 23.0 分。
- [PolicyGuide: From Guarding One Action to Guiding the Whole Workflow](https://arxiv.org/abs/2608.19861) — 把「动作级安全拦截」升级为「流程级引导」：将领域策略编译成工作流图，在用户轮边界调用主动校验器，从持久化图状态给出下一步合规补救；τ²-bench 上 Pass⁴ 从 0.42 升到 0.62（telecom 域 0.19→0.61），同一套工作流可跨 GPT/Claude/Gemini 迁移。
- [Learning how to Forget: Fine-tuning for Long-Context Sparse Attention](https://arxiv.org/abs/2608.19920) — 提出适配任意 KV 缓存策略的稀疏注意力微调法，让模型与「遗忘策略」协同适配，单张 A100 40G 即可跑，效果常超用精确注意力训练的模型；配套开源 KeysAndValues 库。

## 【前端 → AI Agent 转型方向】

- [Vercel × Ora 上线 Is Agentic：给网站做 Agent 体检](https://is-agentic.com) — 输入 URL 跑 118 项检查，评 0–100 分判断 Agent 能否「发现 / 读取 / 理解 / 实际使用」你的站点：不止查 robots.txt、llms.txt，还测 SSR、HTTP 返回、页面结构、可操作按钮，以及 API / OAuth / GraphQL / MCP 接口是否真能被调用；Ora 已扫的 1.4 万站点平均只有 34 分、77% 是 D/F。
- [is-agentic 评分机制拆解（含 MCP / OpenAPI 细节）](https://dev.to/promptway/vercel-shipped-is-agenticcom-here-is-how-the-scoreboard-works-49d3) — 逐项讲清报告怎么读：只读 MCP server 暴露 3 个工具、OpenAPI 在 `/openapi.json`、错误走 RFC 9457、限流 120 req/IP/min；作者实测自家站 74 分并给出可复用的修复 prompt，附一句关键警告——别为凑分虚构不存在的产品能力（比如假装自己有 MCP server）。
- [Mastra 多 Agent 流水线实战：四个 TS Agent 如何不丢状态](https://dev.to/mech_app_ai/mastra-multi-agent-pipeline-coordinating-four-typescript-agents-without-losing-state-2dn5) — 合同分析系统拆成 Parser/Summary/Risk/Query 四个 Agent（各自温度与推理档位不同），全部用 Zod schema 约束结构化输出，Mastra workflow 用 `dependsOn` 建执行图、每步落库后再进下一步，崩溃后按 skip-completed 续跑；文中点明代价——步骤输出必须幂等，否则重试会拿到脏数据。
- [Context Engineering for AI Agents：搭起来容易，上下文难](https://shaam.blog/articles/ai-agent-context-engineering-production-2026) — 论点很值得抄：状态持久化、沙箱、可观测已被 Cloudflare Agents SDK / Vercel AI SDK / Mastra 平台化，定义一个 Agent 只剩四个决策；线上真正翻车的是缺组织上下文导致的「自信地答错」，且 MCP 给的是访问权不是理解力，原始连接器输出会淹掉上下文窗口。
- [AI Agent 开发语言与框架选型指南：Python / TypeScript / Java](http://www.tqpw.cn/news/608631) — 对 TS 团队最有用的一段：Vercel AI SDK 6 已是 TS 侧最成熟工具链，`generateText`/`streamText` 统一接口、内置 Tool Loop 自动多步工具调用、MCP 支持从 experimental 转正、AI Gateway 一个 endpoint 接几百模型带 fallback；同时点出 LangChain API 频繁 breaking change 的坑。
- [Vercel AI Gateway：开放权重模型 token 占比冲到 62%](https://fav0.com/en/) — Guillermo Rauch 披露 8 月开放权重占比 62%（两个月前才 28.4%），闭源降到 38%，且企业采用仍属早期；配合同日 OpenAI 下调 GPT-5 API 价、DeepSeek 取消周末峰谷计价，「按任务成本选型」正式成为主战场。

## 今日值得深入

1. **[Is Agentic](https://is-agentic.com) + [评分机制拆解](https://dev.to/promptway/vercel-shipped-is-agenticcom-here-is-how-the-scoreboard-works-49d3)** — 这是今天对你最有杠杆的一条：118 项检查里绝大多数（SSR、HTTP 语义、结构化数据、可操作元素、OAuth/GraphQL/MCP 接口可用性）正好是十年前端工程化的存量技能，只是评分对象从「人和爬虫」换成了「Agent」。建议拿云笺 CloudNotes 的公开展示页直接跑一次，把报告里的 Essential 失败项当成一份现成的「前端 → Agent 可读性」改造清单；顺手也验证一下自己那套 MCP / JSON API 暴露方式是否真能被外部 Agent 消费。
2. **[MidTool](https://arxiv.org/abs/2608.20314) + [Thinkingbox](https://arxiv.org/abs/2608.19741)** — 一组互补的「工具调用真相」：MidTool 说明工具调用不该靠后训练调 prompt 硬凑，而要在 mid-training 阶段用真实 API / MCP skills 合成语料，把「识别可用性 → 上下文取参 → 组合调用链 → 信息不全时恢复」教进模型；Thinkingbox 则用 pass@1 65% vs pass^20 25% 打掉「跑通一次就算能用」的幻觉，还指出失败往往表现为「干净退出 + 合法工具调用」。对照你的 ToolExecutor / RetryController：评测口径应从「单次成功率」改成 pass^k 可靠性，并把「合法但没达成状态变更」单列成一类失败写进 fail.jsonl。
