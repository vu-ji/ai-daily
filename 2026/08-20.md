## 【arXiv 精选】

> 以下为 cs.AI / cs.CL 当日新提交中与 Agent / 工具调用 / 记忆 / 推理控制最相关、且 HF Daily Papers 未排上的硬核条目。

- [Write, Execute, Refine: From Skill Followers to Skill Optimizers via RL from Execution Feedback](https://arxiv.org/abs/2608.17587) — 用「执行反馈强化学习」让模型从技能跟随者进化为技能优化器，正是技能自迭代的工程化路径。
- [On the Fragility of Self-Improving Agents: Variance, Task Order, and Underspecification](https://arxiv.org/abs/2608.18066) — 揭示自改进智能体在方差、任务顺序与规格不清下的脆弱性，给「让 Agent 自我进化」泼了盆冷水。
- [D2ACCI: A Dual-Loop Diagnostic Protocol for Evidence-Preserving Agent Memory](https://arxiv.org/abs/2608.17756) — 双环诊断协议保证 Agent 记忆的「证据可溯源」，解决记忆被悄悄污染的问题。
- [TRUSS: Towards Task-Reliable and User-Safe Automated Agent Skill Generation](https://arxiv.org/abs/2608.17588) — 面向「任务可靠 + 用户安全」的自动化技能生成，给技能的自动生产加上护栏。
- [Wuying-Browser-Agent: Real-World Centric Fundamental Long-Horizon Browser Agents](https://arxiv.org/abs/2608.17319) — 构建真实世界长周期浏览器操作智能体，工具调用在开放网页环境的落地样本。
- [Token Optimization and Context Window Management in Multi-Agent AI Workflows](https://arxiv.org/abs/2608.17188) — 多智能体工作流中的令牌优化与上下文窗口管理，与「Token 预算」工程实践直接对应。
- [Explicit State Elicitation Is Not Enough: A Controlled Audit of Memory-Policy Classification](https://arxiv.org/abs/2608.17247) — 受控审计表明「显式状态引出」不足以搞定记忆-策略分类，记忆治理比想象中难。
- [Task-Aware Harness Provisioning for LLM Agents in Mission-Critical Infrastructure Operations](https://arxiv.org/abs/2608.17433) — 关键基础设施运维场景下的任务感知 harness 配置，把 harness 推向生产级容错。

## 【前端 → AI Agent 转型方向】

- [Agent Plugins 1.0：Skills + MCP 跨平台打包](https://en.aistacknav.com/agent-plugins-1-0-skills-mcp-codex-copilot-vscode) — AWS/Anysphere/微软/OpenAI/Vercel 联合发布、Google 8/12 加入核心维护者的开放标准，已在 VS Code、Copilot CLI/SDK/App GA；用 `plugin.json` + `skills/` + `mcp.json` 把能力一次开发、多端适配，是分发 Agent 技能的事实标准。
