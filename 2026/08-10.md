# AI 每日动态 · 2026-08-10

> 今日主线：**在检索与记忆这一层，「少上模型」正在反复赢过「多上模型」**。周末三篇论文从完全不同的场景撞出同一个结论：① 在 690 个技能的技能库上，给检索加一层 LLM 生成的类型化知识图谱，**比强基线排序器还差 11.2 分**（p=0.0007），而且 98.6% 的边连的是排序器早就一起召回的技能；② 在 780 页政府财报上，扔掉 embedding、改用「词法搜索 + 结构导航 + 有界跨度读取」三个确定性操作走 MCP 暴露给 agent，正确率 **58.8% vs 稠密检索 15.7%**；③ 把屏幕活动用**零模型的确定性管线**编译成 agent 记忆，86× 压缩、68ms、问答准确率 98.4%，而同一份数据让 LLM 写摘要只有 66–80%。
>
> 这三件事对前端的意义是一样的：**检索层和记忆层的胜负手正在从「上什么模型」转向「解析、索引、缓存、确定性产物」——这是工程活，不是 ML 活。** 另一条线上，FinEvo-Bench 给出两个反直觉发现（skill-only 进化优于 memory-only 和二者组合；rubric 反馈优于参考答案反馈），而 Mastra 刚好在 7/28 上线了 Rubric Scorers。

### 论文

- [Activity Frames: Deterministic Screen-Activity Compilation for Agent Memory and Replay](https://huggingface.co/papers/2608.05784) — 今天最该读的一篇。出发点很扎心：**computer-use agent 今天的记忆记的是「用户说了什么」，不是「用户做了什么」，所以每次都在用前沿模型的全价重新推导用户早就做过的例行操作。** 方案是把被动采集的屏幕流用**零模型确定性管线**编译成带类型的「活动帧」（应用、站点、时序、输入量 + 指回原始行的证据指针），输出**逐字节可复现、可缓存、可机械审计**。单人 51 天 128,756 帧语料上：一天的原始采集压成 prompt-ready 上下文块**小 86 倍、耗时 68ms**，agent 读这个块回答当天问题准确率 **98.4%**，而 LLM 摘要同一份数据只有 66–80%——**中端模型读编译块即可追平前沿模型**
- [EnvACE: Internalizing Environment Dynamics via World Rehearsal](https://huggingface.co/papers/2608.06197) — 腾讯（38 票）。训练长程工具使用 agent 的老大难是「可执行环境造起来太贵」，EnvACE 干脆**取消训练期的外部环境交互**：策略先生成工具调用，再**自己扮演环境**产出该动作诱导的响应，然后基于这个「排练出来的响应」继续决策，两个角色用任务成功奖励端到端联合优化。在 BFCL-v4 / τ²-Bench / VitaBench / FinMCP-Bench 上全面超过环境扩容基线；更有意思的是**推理期也能用**——执行前先私下排练一遍再落子，[代码已开源](https://github.com/Within-yao/EnvACE)
- [OSReward: Standardized Evaluation for Cross-Platform Computer-Use Reward Models](https://huggingface.co/papers/2607.28609) — 港大 NLP（67 票，今日榜眼）。computer-use agent 的奖励模型一直是各做各的、跨平台无法比较，这篇把评测标准化立起来；想训 GUI agent 的人，这是绕不开的一块地基
- [FinEvo-Bench: A Longitudinal Benchmark for Self-Evolving Agents](https://huggingface.co/papers/2608.06144) — 北航 + 阿里 Qwen DianJin。**纵向**基准：120 个真实金融案例、20 个业务场景，同一 scene 下 6 个共享专业流程的相关案例串成任务流，专门测「前面的经验有没有让后面做得更好」。详见下方 arXiv 段落的两个反直觉结论

## 【arXiv 精选】

> 来源：arXiv cs.AI / cs.CL 当日新提交（Fri, 7 Aug 2026 批次，8 月 6 日投递）。因 08-08/08-09 未出刊，本段从该批次中选取此前未收录的条目。今日两条主线：**检索/记忆层的「去模型化」**，以及**自进化 agent 的经验沉淀方式**。

- [Comparative Approaches to Agent Retrieval over Large Skill Libraries](https://arxiv.org/abs/2608.06196) — **今日必读，一篇漂亮的证伪。** 在 690 个技能的语料上对比两种技能检索方案：① 词法 + 稠密嵌入的混合排序器；② 编码前置条件、数据流、执行顺序的**类型化知识图谱**。117 条真实（非自写）查询上，混合排序器 hit@5 为 **73.5% ± 8.0**；而在同等 token 预算下用图谱邻居替换额外排序结果，**显著更差 11.2 分（p = 0.0007）**。机制解释很硬：图谱的候选边取自排序器已经搜过的同一个嵌入邻域，**98.6% 的类型化边连接的是排序器早就一起召回的技能**——作者称之为「预过滤拓扑上界」，图谱能丰富关系语义，但**无法扩展检索触达范围**；排序器漏掉的查询有 73% 通过图谱根本不可达。附带一记警钟：**用作者自写的查询做评测会把 hit@5 高估最多 44 分**，足以把上面所有结论完全掩盖
- [Beyond Top-K: Replacing Black-Box Retrieval with Interpretable Agentic Operations](https://arxiv.org/abs/2608.06305) — 上一篇的正面版本。论点是「切块 → 嵌入 → top-k」这套设计对财报、审计报告、监管申报这类文档**结构上就不成立**：780 页政府财报里 **86.8% 的内容行是表格行**，成千上万个近乎相同的数字挤在同一个嵌入空间，而一个数字的单位继承自**中位数 13 行以外**的表头——切块边界常常把数字和「它是万还是亿」切开，直接两个数量级的错。方案 READ 让 agent 用三个确定性操作**直接读原文**（归一化词法搜索、结构导航、有界跨度读取），全部走 MCP 暴露，于是**一条轨迹就是可回放的审计链，而不是一个不透明的相似度分**。51 道核验题上 READ **58.8%**，稠密检索 15.7%（调优后 35.3%，READ 仍领先 23.5 分）；同样的 agent 循环但只给 top-k 工具只有 27.5%——**增益来自接口，不来自迭代**。作者同时诚实地报告了证据不支持的部分：**BM25 与 READ 统计上无法区分**，所以本文分开的是「嵌入 vs 无嵌入」，不是「agentic vs 词法」
- [FinEvo-Bench: A Longitudinal Benchmark for Self-Evolving Agents in Professional Financial Workflows](https://arxiv.org/abs/2608.06144) — 同一 Qwen3.7-Max 主干下横评四种自进化脚手架，配对的非进化对照组用来剥离出「保留经验」带来的净增益。Letta 进化后得分最高（91.65）且合规问题最少（0.09/任务），Codex 自进化增益最大（+19.37）；整体进化条件提升 9.33–19.37 分、合规问题减少 0.12–0.44/任务，且**同 scene 内第 4–6 个案例的增益比第 1–3 个高 6.10–8.70 分**（经验确实在累积）。两个反直觉发现值得单独记下来：**① 在 Claude Code 上，只进化 skill 比只进化 memory、以及 memory+skill 组合都更好；② 四种脚手架上，rubric 式反馈一致优于给参考答案的反馈**
- [Learning When to Trust via Selective Context Preference Optimization](https://arxiv.org/abs/2608.06377) — 把「抗干扰」这个目标本身拆穿了：训练模型抵抗误导性上下文，会养出一个**对所有上下文一视同仁地不信**的模型——看着很鲁棒，实际在上下文值得信的时候毫无用处。作者把问题重述为**选择性信任**，出了 MIST 基准（每道题渲染成干净 / 误导 / 正确上下文 / 无关上下文四种匹配条件）和 SC2W 指标（专门数「误导信号把原本答对的题翻成错」的次数），发现这种易感性**普遍存在**；SCOPE 的做法是在四种条件上均衡配对做 DPO，而不是只拿误导样本训。[数据集已开源](https://huggingface.co/datasets/worldbench/MIST-Bench)
- [Contextual Information Policy Optimization for Search Agents](https://arxiv.org/abs/2608.06128) — 搜索 agent 的一个隐蔽病灶：现有方法只奖励最终答案或中间进展，**从不检查检索之后的动作是否真的建立在检索到的证据上**，于是模型学会了「先用内部知识下结论、再用检索去确认它」的**先验驱动推理**，形成确认偏误。CIPO 给受检索信息影响的推理动作分配稠密的回合级信用，与全局结果奖励结合；**不需要人工过程标注，也不需要额外奖励模型**，七个域内外基准上显著降低了先验驱动推理的比例
- [AppDeltaWorld: Transition-Grounded Delta Code World Model for Mobile GUI Agents](https://arxiv.org/abs/2608.05891) — 给移动端 GUI agent 做世界模型，但不预测整屏状态，而是预测**状态转移的 delta 并落成代码**；和 EnvACE 的「世界排练」是同一思路的两个变体，都在回答「怎么不靠真实环境也能训 agent」
- [Benchmarking the Benchmarks: Evaluating Benchmarks for Conversational Agents](https://arxiv.org/abs/2608.06329) — 元评测：对话 agent 的基准本身靠不靠谱。和上面那篇「作者自写查询高估 hit@5 达 44 分」放在一起读，今天 arXiv 其实在提醒同一件事——**你的评测集设计方式，可能比你选的方法更能决定结论**

- [AI Agent 框架全景对比：Python vs TypeScript，2026 年该怎么选](https://f.mffb.com.cn/a/484960.html) — 一份能直接照着走的决策树，以及一个正在成为主流的结论：**不是二选一，而是分层**——TypeScript 负责编排层 / 用户端 UI / 实时交互（Vercel AI SDK、Mastra、LangGraph.js），Python 负责计算层 / 模型推理 / 数据处理，两层之间用 MCP 或 gRPC 打通。另附「大厂 SDK 涌入、框架中立已成历史」的判断：OpenAI Agents SDK / Claude Agent SDK / Google ADK 各自绑定自家模型，通用框架换来的是灵活性、厂商 SDK 换来的是最佳体验

## 今日值得深入

> 以下两条作为转型学习重点参考，建议精读。

1. **检索与记忆层正在「去模型化」，而确定性工程恰好是你的主场：[Agent Retrieval over Large Skill Libraries](https://arxiv.org/abs/2608.06196) + [Beyond Top-K / READ](https://arxiv.org/abs/2608.06305) + [Activity Frames](https://arxiv.org/abs/2608.05784)** — 这三篇今天从三个毫不相干的场景（技能库检索、长文档问答、屏幕活动记忆）撞出同一个结论：**在检索和记忆这一层，加模型往往不如加确定性结构。** 第一篇证明给强排序器上一层 LLM 生成的知识图谱**反而掉 11.2 分**，因为图谱的边取自排序器已经搜过的同一个嵌入邻域，98.6% 的边毫无新信息；第二篇证明在表格密集的长文档上扔掉 embedding、改用词法搜索 + 结构导航 + 有界跨度读取，**58.8% vs 15.7%**，而且明确指出**增益来自接口设计（可回放的操作序列），不来自 agent 多迭代几轮**；第三篇更极端——**整条管线零模型**，86× 压缩、68ms、98.4% 准确率，把 LLM 摘要的 66–80% 按在地上。
   为什么这对你格外有利：这三套方案的核心工程量分别是**倒排索引与查询归一化、文档结构解析与跨度定位、流式数据的确定性编译与缓存**——全是前端/工程侧的老手艺，一行 ML 代码都不需要。反过来说，如果你现在的 RAG 方案是「切块 → 嵌入 → top-k」的默认三件套，今天这三篇是明确的红旗。
   动手路径建议：拿你手上任意一个 RAG 或技能检索模块做一次对照实验——① 保持现有稠密检索；② 加一路 BM25 / 归一化词法搜索 + 一个「按结构跳转 + 读指定行区间」的工具，把这两个工具通过 MCP 暴露给 agent，**不给它 top-k**。对比正确率与可解释性。**特别注意用「非自己写的」查询来评测**——第一篇实测作者自写查询会把 hit@5 高估最多 44 分，足以让你得出完全相反的结论。

2. **经验沉淀应该沉在 skill 而不是 memory，反馈应该给 rubric 而不是标准答案：[FinEvo-Bench](https://arxiv.org/abs/2608.06144) + [Mastra Rubric Scorers](https://mastra.ai/blog/introducing-rubric-scorers-for-mastra-agents)** — 接着上周「技能池污染不可逆、必须做准入门禁」的话题，这周补上了另外半张图：**该往哪里沉淀，以及该用什么反馈。** FinEvo-Bench 在同一主干下横评四种自进化脚手架，两个发现都反直觉——① 在 Claude Code 上，**只进化 skill 的效果好于只进化 memory，也好于 memory + skill 组合**（组合反而互相干扰）；② 四种脚手架一致地，**rubric 式反馈比给参考答案的反馈得分更高、合规问题更少**。整体进化增益 9.33–19.37 分，且同场景第 4–6 个案例的增益明显高于第 1–3 个——经验确实在累积，但前提是沉对了地方。
   翻译成工程语言：**「记住这次对话」的价值远低于「把这次做对的做法固化成一条可复用、可校验的 skill」**；而评估 agent 时给「标准答案」相当于给它一个可以过拟合的目标，给「评分量表」才是在教它约束。这个区别前端也不陌生——它就是 snapshot 测试与契约测试的差别。
   如果你在攒自己的 agent 工程体系，本周可做的两件事：**① 把现有的「记忆」条目过一遍，凡是能改写成带输入输出契约的 skill 的，全部改写，剩下纯上下文的才留在 memory 里；② 给你的 agent 评估加一层 rubric**——Mastra 的 Rubric Scorers 提供了现成实现，即使你不用 Mastra，照着「多条独立评分标准 + 每条独立打分」的形态自己写一个也就是半天的事。
