# AI 每日动态 · 2026-08-06

> 今日主线：**Harness（脚手架）正式站到台前，而「个性化记忆」同时被三篇论文按在地上摩擦**。ZJUNLP 的 OneDayAgent 用同一套 harness 跨 5 个不同 backend 不调优就拿下 SOTA，arXiv 同批还有 Argus（通用 agentic runtime）、Skill-Use（LLM 在 harness 里真的会用技能吗）；工程侧 Mastra 连着三天发沙箱、文件系统、反馈分析，把 harness 直接平台化。反方向上，HKUST 的 Personalization Mirage、腾讯的 When Memory Lies、以及 FinPerMA / SafeCommit 集体指出：Agent 的用户画像是编的、空间记忆会过期、而且模型自查越多越自信。**结论对前端很友好——价值不在模型，在你围着模型搭的那一圈工程；但别急着写记忆层。**

### 论文

- [OneDayAgent: Towards a Long-Horizon Harness for Autonomous Agents](https://huggingface.co/papers/2608.05013) — 浙大 ZJUNLP，今日最值得读的一篇：把开放式请求转成「拆成有界子任务 → 上下文压力下维护执行记忆 → 对最终交付物验证并修复」的托管流程，AgentIF-OneDay 104 个任务上以 GLM-5.2 后端拿下 0.821 的新 SOTA；**关键在于同一套 harness 不调优跑通了 3 个模型家族的 5 个 backend**
- [The Personalization Mirage: How LLMs Fabricate User Profiles, and Why Self-Monitoring Misleads](https://huggingface.co/papers/2608.04570) — HKUST，今日 29 票：LLM 会凭空编造用户画像，而让它「自我监控」不但纠不过来，反而会给错误画像加上更高的置信度——正在写用户记忆层的人务必先看
- [ToolArtist: Tool-Using Unified Multimodal Models for Agentic Image Generation](https://huggingface.co/papers/2608.04436) — 今日票数第一（33 票）：让统一多模态模型学会调工具而不是一把梭生成，图像生成从「一次出图」转向「规划 + 调用编辑工具」的 agentic 范式
- [When Memory Lies: An Empirical Study of Spatial Memory Staleness in VLM Agents](https://huggingface.co/papers/2608.04574) — 腾讯：实证 VLM Agent 的空间记忆会「过期而不自知」，环境变了但记忆还停在旧状态，长时程具身 Agent 的一个隐蔽故障源
- [Toward Skill-Native LLMs: Skill Entropy for Benchmarking and Training Long-Horizon Reasoning](https://huggingface.co/papers/2608.05139) — 普林斯顿提出「技能熵」这个可量化指标，用来衡量并训练模型在长时程推理中的技能调度多样性
- [Agent Against Agent: An Agentic System for Automatic Prompt Injection Red Teaming](https://huggingface.co/papers/2608.05108) — 宾州州立：用 Agent 自动给 Agent 做提示注入红队测试，把安全测试本身做成可持续跑的流水线

## 【arXiv 精选】

> 来源：arXiv cs.AI / cs.CL 当日新提交（2608.04xxx–2608.05xxx）。今日两条主线极其清晰：**harness / runtime 的工程化**，以及**记忆与推理监控的可靠性危机**。

- [Skill-Use: Can LLMs Actually Use Skills in Agentic Harnesses?](https://arxiv.org/abs/2608.04828) — 标题即灵魂拷问：给 Agent 灌一堆 skill 之后，模型在实际 harness 里到底会不会用、用得对不对；正在给 Agent 堆 skill 库的人的必读证伪材料
- [Diagnosing Tool-Selection Reasoning in LLM Agents with Canary Tools](https://arxiv.org/abs/2608.04719) — 极其实用的方法：往工具集里塞「金丝雀工具」（诱饵工具）来诊断 Agent 的工具选择推理是真理解还是靠名字瞎猜，这个技巧今天就能加进自己的 eval
- [Argus: A General-Purpose Agentic Runtime for Long-Horizon Reasoning](https://arxiv.org/abs/2608.05144) — 面向长时程推理的通用 Agent 运行时，与 OneDayAgent 构成同一天的两份 harness 方案，可对照阅读
- [Hierarchical Graph Memory for LLM Agents with Path-level Localization and Rewrite](https://arxiv.org/abs/2608.05095) — 用分层图组织 Agent 记忆，支持路径级定位与改写，比「一个向量库拍平所有记忆」更接近可维护的数据结构
- [Caching for the Future: Scrub Jay Episodic Memory Principles for Agent Memory Systems](https://arxiv.org/abs/2608.04746) — 借鉴灌丛鸦（会记住「什么食物、藏在哪、什么时候会坏」）的情景记忆原理设计 Agent 记忆缓存，给记忆条目引入时效性与衰减
- [SafeCommit: Certifying When Memory-Grounded Agents May Safely Act](https://arxiv.org/abs/2608.04289) — 不解决记忆准不准，而是给「基于记忆的 Agent 什么时候可以放心执行动作」做形式化认证，工程上可以直接抄成一道 gate
- [Chain-of-Thought Monitoring Can Be Unreliable in Implicit-Influence Settings](https://arxiv.org/abs/2608.04735) — 给「读 CoT 就能监控 Agent 行为」这个流行假设泼冷水：存在隐式影响时，思维链说的和模型实际做的可以完全脱节
- [ContextWeave: A Real-World Workflow Benchmark](https://arxiv.org/abs/2608.04830) — 真实工作流基准，把 Agent 评测从孤立任务挪到跨工具、跨步骤的连续工作流上

## 今日值得深入

> 以下两条作为转型学习重点参考，建议精读。

1. **Harness 是可迁移的工程资产，而这正是前端的主场：[OneDayAgent](https://huggingface.co/papers/2608.05013) + [Skill-Use](https://arxiv.org/abs/2608.04828) + [harness 成本基准](https://www.brianletort.ai/downloads/ai-stack-weekly-2026-W28.pdf)** — OneDayAgent 这篇最该注意的不是 0.821 的 SOTA，而是那句「同一套 harness 跨三个模型家族的五个 backend 不调优仍然有效」。合上 Databricks 那组「换 harness 成本差 2 倍、调 harness 能把开源模型拉到接近 Opus 质量」的数据，结论已经不用再论证了：**你写的拆解逻辑、执行记忆管理、交付物校验修复这一圈代码，是不随模型换代贬值的资产，而模型本身正在快速商品化。** OneDayAgent 的三段式结构（bounded subtasks / execution memory under context pressure / verify-and-repair the deliverable）可以原样当成自己项目的骨架来抄。动手路径建议：拿一个现有的 AI SDK 或 Mastra 小项目，先补上第三段「交付物验证并修复」——这是最容易被跳过、也是收益最直接的一段；再用 [Canary Tools](https://arxiv.org/abs/2608.04719) 的诱饵工具法给自己的工具集做一次体检，看看 Agent 到底是真在选工具还是在猜名字。

2. **先别急着写记忆层：[Personalization Mirage](https://huggingface.co/papers/2608.04570) + [When Memory Lies](https://huggingface.co/papers/2608.04574) + [SafeCommit](https://arxiv.org/abs/2608.04289)** — 今天这三篇合起来是一记警钟。Personalization Mirage 最狠的一点不是「LLM 会编造用户画像」，而是**让模型自我监控会让它对编造出来的画像更自信**——也就是说，「加一步自查」这个前端最容易想到的补丁在这里是负作用。When Memory Lies 补上另一半：就算记忆当初是对的，环境变了它也不会自己失效。所以正确的工程姿势不是「存得更多」，而是给每条记忆强制带上**时间戳 + 来源 + 置信度**，读取时先校验新鲜度再决定要不要注入上下文；[Scrub Jay 那篇](https://arxiv.org/abs/2608.04746)的衰减机制和 SafeCommit 的「认证记忆何时可安全行动」正好提供了这两道闸门的设计参考。如果你手上已经有在跑的记忆层，今天最值得做的一件事是：**统计一下有多少条记忆是模型推断出来的而非用户明说的**——那部分就是幻觉的存量库存。
