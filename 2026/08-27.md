## 【arXiv 精选】

### cs.AI（当日新提交 2608.24xxx 段，8/25 提交）

- [Recuris: Recursive Experiential-Working Memory Evolution for Long-Horizon Agent Harnesses](https://arxiv.org/abs/2608.24876) — 递归「经验-工作记忆」架构：工作记忆引导技能选取、把执行转成可定位失败的证据、以验证门槛局部更新技能记忆；37 组里 35 组提升，tau-bench 给 GPT-5.6 +17.8、最长任务 +32.2，长程失败降 80%。
- [CAFE: Self-Improving Search Agents Need Co-Evolving Feedback](https://arxiv.org/abs/2608.24794) — 搜索 Agent 需「协同演化反馈」：共享参数模型在 agent/critic 角色间交替，仅靠一方会触顶，两者交替持续提升，7 个 agentic 搜索基准平均领先且跨域保留增益。
- [SMITH: Joint Optimization of Tool Creation and Use](https://arxiv.org/abs/2608.24571) — 单策略 RL 联合训练「造工具」与「用工具」，三轴奖励分别抓 schema/代码/结果失败；4B Qwen3 在 13 个程序推理任务达 79.8 宏平均，反超未训练的 30B 工具编写器。
- [The Handoff Tax: Continuing Non-Native Trajectories in LLM Agents](https://arxiv.org/abs/2608.24358) — 模型升降级「切换税」：LC→HC 全轨迹接管仅追回不到一半质量差距却多花大量成本，降级（downshift）反而性价比更优——直接对应三级路由（light/heavy/cloud）的成本-质量权衡。
- [StarHarness: Evolving Harnesses with Stratified Search for Enterprise Environments](https://arxiv.org/abs/2608.24804) — 冻结权重、只演化 harness（提示/工具接口/skills/MCP/子 Agent 结构），按基线失败分层搜索；ITBench/EnterpriseOps/AutomationBench 上比默认 harness 提 20–35pp，且跨 GPT/Qwen 家族免重训迁移。

### cs.CL（当日新提交 2608.24xxx 段，8/25 提交）

- [BrowserForge: Scaling Web Episode via Parallel Browser Sandboxes](https://arxiv.org/abs/2608.24848) — 并行浏览器沙箱从开放网络规模化造 Web Agent 轨迹：203,238 条、每条来自不同真实站点；Proposer-Solver 双 Agent 产出可验证轨迹，微调多模态模型把 Online-Mind2Web 成功率从 25.66% 拉到 33.33%。
- [SkillForge: Evolving Verifiable Skills for RL Agents](https://arxiv.org/abs/2608.24747) — 给 RL Agent 加「持续验证+多路径归纳」的技能演化：技能库不再是 append-only，而是显式调用并经环境交互验证；ALFWorld/WebShop/AppWorld 上稳定超 SkillRL。
- [Who is the Agent to Blame? Localizing Faithfulness and Citation Mistakes in Agentic Deep Research](https://arxiv.org/abs/2608.24306) — 把 Deep Research 错误定位到具体 Agent：四类错误 taxonomy（幻觉/未引输入/未引输出/引用不足），AI-Q 报告 84.7% 错误源自 orchestrator，两处简单干预把引用召回 +5% 不降质量。
- [MemUse: Moving Memory Evaluation from Direct QA to Natural Integration](https://arxiv.org/abs/2608.24189) — 记忆评估该看「自然融入」而非「直接问答」：同一系统 Direct QA 78.8%，但在真实对话里只引用了 7.9% 的事实（71 分落差），自然融入度才与满意度相关（EMNLP 2026）。

## 【前端 → AI Agent 转型方向】

- [Best Tools & Libraries to Actually BUILD Your Own AI Agents（2026 按栈选型）](https://dev.to/ayabongaqwabi/best-tools-libraries-to-actually-build-your-own-ai-agents-with-2j) — 把框架按「氛围」分组：代码优先（LangGraph/Mastra/Vercel/ADK/AutoGen）、可视化（n8n/Dify/Flowise），并给出「Next.js 老手→Mastra」「要强控制→LangGraph」的 2026 行动清单。
- [智能体框架的赛道地图](https://www.cnblogs.com/weiluliaokeji/p/22670730) — 中文选型矩阵：LangChain 系/官方 SDK/CrewAI/AutoGen/Dify/LlamaIndex/Mastra 七维横评，结论「谁在解决什么问题」而非「谁最强」，适合做技术雷达底稿。
- [个人开发者 AI Agent 落地：从选型到上线的完整路径](https://www.toutiao.com/article/7675946954610573843/) — 实操干货：工具四要素（名称/描述/类型化参数/执行函数）、「清晰工具优先于提示词」、硬性停止条件（递归上限 10 次、工具调用次数限制）防 API 预算烧穿。
- [LangChain.js vs Mastra vs Vercel AI SDK（TS 框架深度横评）](https://dev.to/agdex_ai/typescript-ai-agent-frameworks-in-2026-langchainjs-vs-mastra-vs-vercel-ai-sdk-43pd) — 含可运行代码对比：Mastra 的 typed workflow + 本地 eval 套件、Vercel 的 Generative UI、LangGraph.js 的 human-in-the-loop 断点，给「前端→Agent」最贴手的迁移样板。
