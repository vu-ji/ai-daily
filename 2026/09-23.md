## 【arXiv 精选】（cs.AI / cs.CL，聚焦 Agent / 工具调用 / 记忆 / 推理控制）

- [Grow the Harness, Not the Context](https://arxiv.org/abs/2609.26760) — 提出失败引导的「harness 生长」范式：从不含控制器的脚手架出发，把反复出现的控制决策固化成可执行代码，LLM 只留语义推理，BrowseComp-Plus / WebArena 上 LLM 调用降 76–92%、成本降 74–99%，4B 小模型也稳住 44.7–45.3% 成功率。
- [Measuring the Serving Stack Instead of the Model](https://arxiv.org/abs/2609.26693) — 证明本地工具调用评测结果常被 Ollama / llama.cpp / vLLM / SGLang 的服务层行为左右而非模型本身，同一请求跨栈表现不一、turn-pooled 与 per-instance 估计可差 55 个点，并给出把 serving 行为纳入评测协议的 checklist。
- [CliffCompaction: Cost-Efficient Compaction for Long-Horizon Coding Agents](https://arxiv.org/abs/2609.26779) — 面向长程编码 Agent 的低成本上下文压缩，直接对接「编码 Agent 跑久了上下文撑爆」的真实痛点。
- [DTOC: Dynamic Tool Output Compression](https://arxiv.org/abs/2609.26121) — 把工具输出完整存外部记忆、上下文里只放占位符并在需要时可逆还原；消融显示「可逆」是性能关键，可逆版显著降低 context 成本而不掉点。
- [MemoryAthena: Adaptive Routing over Latent and Generated Memories](https://arxiv.org/abs/2609.25853) — 提出记忆不只可检索还可「生成」，以直接检索为锚训练轻量因果路由头决定生成记忆何时介入，把「记忆路由」本身变成可学习对象。
- [SpeakerMem-R1: Speaker-Centered Dual-Track Memory](https://arxiv.org/abs/2609.26780) — 多方对话下的说话人中心双轨记忆，解决多角色场景下记忆串扰与归属问题。
- [Agensh: Scaling Organizational Intelligence to 1,024 Agents](https://arxiv.org/abs/2609.26781) — 微软把组织级多智能体规模推到 1024 个 Agent，研究协作结构与调度在超大规模下的行为。
- [FIRE: Failure-Informed Runtime Engineering for Reliable LM Agents](https://arxiv.org/abs/2609.26048) — 以失败信息驱动 Agent 运行时工程，把失败模式前置进运行期设计而非事后打补丁。
- [REFLEX with Jev for Efficient Selective Control in LLM Agents](https://arxiv.org/abs/2609.26532) — 用选择性控制降低 Agent 推理开销，只在必要环节上重控制。
- [JEV-as-a-Judge: Accept When Confident, Escalate When Unsure](https://arxiv.org/abs/2609.26550) — 提出「自信时接受、不确定时升级」的判定策略，给 Agent 的自动验收环节提供可操作的分流准则。
- [CoVeR: Coverage-Based Routing of Verifier Calls in Agentic Retrieval](https://arxiv.org/abs/2609.26086) — 按覆盖率路由验证器调用，在 Agentic RAG 中把验证算力花在刀刃上。
- [Beyond Repeated Sampling: Learning Search Policies for LLM Reasoning](https://arxiv.org/abs/2609.26704) — 不再靠重复采样堆 pass@k，而是学习推理搜索策略，属于推理控制的正本清源。

## 今日值得深入

1. **[Grow the Harness, Not the Context](https://arxiv.org/abs/2609.26760)** — 这篇几乎是为 pi-agent 的 Skill / harness 架构量身写的注脚：它用实验证明「把反复出现的控制逻辑从模型上下文里搬出去、固化成可生长的代码」能同时降本 74–99% 并让 4B 小模型维持 44%+ 成功率。核心机制三件套（函数级执行轨迹定位失败 → 联合修复失败窗口 → 成功优先的留出集闸门回滚）可以直接映射到你 harness 里的 Skill 更新流程：Skill 的每次改动都该带验证集 + 回滚闸门，而不是无节制往 prompt 里堆策略。**建议动作**：对照论文的三件套检查一遍自己 Skill 的更新路径，缺哪环补哪环。

2. **[Measuring the Serving Stack Instead of the Model](https://arxiv.org/abs/2609.26693)** — 对做 local-first Agent 的人是当头一棒：你测到的「模型不会调工具」，很可能只是 Ollama 的静态模板标志把该模型拒了，或者 harness 没把 rejection / retry-exhausted 存成结构化失败元数据，于是被误判成 0% 保真度。论文给的 checklist（把 serving 行为纳入评测协议、区分 turn-pooled 与 per-instance 估计、注意约束解码会导致不终止）应当直接写进本地 Agent 的评测脚本。**建议动作**：在你的本地 tool-use 评测里先加一层「失败原因结构化落盘」，再谈模型能力对比。
