## 【arXiv 精选】

- [Designer-RSI: Evolving Procedural Memory for Agentic Graphic Design](https://arxiv.org/abs/2609.22086) — 从用户流量中演化「程序性记忆」，让设计 Agent 复用过往方案而非每次从零生成
- [An Interpretable Memory Decision Controller for LLM Agents](https://arxiv.org/abs/2609.22043) — 三信号互补（置信度/一致性解耦）的可解释记忆决策控制器，决定何时写入/读取记忆
- [RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents](https://arxiv.org/abs/2609.22000) — 可验证的混合型电脑操作 Agent 训练/评测环境，覆盖真实软件交互
- [AutoViewMem: Self-Configuring Orthogonal Views for Conversational Long-Term Memory](https://arxiv.org/abs/2609.21940) — 为对话长期记忆自配置正交视图，缓解不同话题记忆互相干扰
- [NemotronLabs VoiceChat: Open Full-duplex Speech-to-Speech with Tool Calling](https://arxiv.org/abs/2609.21967) — 开源全双工语音模型，原生支持工具调用，适合语音 Agent / 电话场景
- [GUARD: Natural Forgetting in Large Reasoning Models](https://arxiv.org/abs/2609.21677) — 用引导式答案-推理蒸馏让大推理模型「自然遗忘」，控制推理链膨胀
- [DENSE: Distilling Agent Trajectories into Evidence-Grounded Shortcut Trees](https://arxiv.org/abs/2609.21423) — 把 Agent 轨迹蒸馏为证据快捷树，支持自我精炼与快速复用
- [ArenaFlow: Hierarchical Credit Propagation for Open-Ended Agent RL](https://arxiv.org/abs/2609.21378) — 从轨迹排序到分层信用传播，改进开放式 Agent 强化学习的奖励分配
- [When Better Turns Do Not Make Better Agents](https://arxiv.org/abs/2609.21187) — 揭示单步指标（下一轮质量）与整体工作流成功的差距，诊断 Agent 评估偏差
- [CodeMidas: Scaling Agentic Coding RL Environments from Code Itself](https://arxiv.org/abs/2609.22068) — 从代码本身自动扩展编码 Agent 的 RL 训练环境，降低环境构建成本

## 今日值得深入

1. **记忆的可控性与去干扰** — [Memory Decision Controller（2609.22043）](https://arxiv.org/abs/2609.22043) × [AutoViewMem（2609.21940）](https://arxiv.org/abs/2609.21940)：前者给出「何时写/读记忆」的可解释判据，后者用正交视图解决记忆互相干扰。两者直接对接你 local-first Agent（Loomry / CloudNotes）的记忆层设计——记忆不是无脑 append，而要有「写入时机 + 检索隔离」两层控制。
2. **前端栈落地 Agent 的生产骨架** — [Vercel eve（「Agent 的 Next.js」）](https://github.com/vercel/eve) × [Mem0 原生记忆集成](https://vercel.com/marketplace)：ev0 把「Next.js 式约定」搬到 Agent（路由/部署/预览开箱即用），Mem0 解决跨会话长期记忆的托管接入。前端转 Agent 不必从零造轮子，用这套组合即可在 TS 栈上跑起带持久记忆的生产级 Agent。
