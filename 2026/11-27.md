## 【arXiv 精选】（cs.AI / cs.CL · 11-26 公告批次）

- [HoMe: Toward Practical Harness Optimization of Memory Systems for AI Assistants](https://arxiv.org/abs/2611.34624) — 清华：记忆系统的 harness（代码/提示/配置）也可自动优化——评估驱动迭代 + 会话级版本化 + 执行轨迹定位失败组件，ReMe 在 LongMemEval-S/BEAM 上性能提升且查询 token 大降，[代码开源](https://github.com/agentscope-ai/ReMe)
- [TransHarness: From Benchmark Overfitting to Transferable Harness Evolution](https://arxiv.org/abs/2611.33757) — 从同任务成败对比中进化 harness 干预策略，跨任务回放 + 独立语义选择防止基准过拟合；仅 300 条测试分布外源轨迹，DeepSWE v1.1 76.4%、Terminal-Bench 2.1 95.5%，超最强基线 GPT-6 Astra 2.4/5.6 分
- [TASK Memory: Beyond Text-Only Memory with Activation Steering and Knowledge Editing](https://arxiv.org/abs/2611.34762) — 文本记忆 + 激活引导 + 知识编辑共享同一模型内地址，专治"检索到了却不照用"的使用幻觉：memory-ignoring 最高 46% → ≤1.5%，3,000 条记忆库仍超 BM25 RAG 16.4pp
- [When Skills Fail to Compose: Compatibility and Retention in Language Models](https://arxiv.org/abs/2611.34398) — 独立习得的软提示技能单次调用组合准确率仅 ≤7.6%（拆成两次调用 88–100%），同操作块之间不可互换；自进化 agent 建技能库必须同时评估兼容性、保持与迁移（[代码开源](https://github.com/YanLin-Quinne/SkillCompatibility)）
- [What Does Skill Lift Actually Measure? A Source-Code-Level Audit of SkillsBench](https://arxiv.org/abs/2611.33943) — 对 7,554 次试验的源码级审计：所谓"技能负收益"多为运行采样噪声（58% 的单元不可能下降），基于无技能分数的门控策略在打乱标签后仍"+4–7pp"，暴露选择偏倚（[复现脚本](https://github.com/rrrrr4788/skillsbench-lift-reanalysis)）
- [vSFT: Learning to Verbally Tune Agents at Test Time](https://arxiv.org/abs/2611.34440) — 测试时"语言监督 + 权重更新"闭环：supervisor 从失败轨迹生成语言监督，超网络转成低秩权重更新；Qwen3-4B 在 ALFWorld/WebShop 上超 GRPO 8.7/4.8 分、超 Reflexion 13.9/18.2 分
- [MeterRouter: Budget-Aware Dynamic Routing for Multi-Agent Systems](https://arxiv.org/abs/2611.34327) — 按查询级货币预算动态合成多智能体协作图（角色/模型/拓扑/终止条件联合决策），GRPO 联合精炼，比最强 MAS 路由器省 82% 成本

## 今日值得深入

1. **[HoMe（2611.34624）](https://arxiv.org/abs/2611.34624) × [TransHarness（2611.33757）](https://arxiv.org/abs/2611.33757)** — 今天最硬的一组组合证据：harness（含记忆系统的 harness）可以不碰模型权重、靠"评估驱动 + 失败轨迹定位 + 跨任务泛化约束"自动进化。HoMe 的会话级版本化与 smoke test/自适应采样直接可搬进 local-first Agent 的记忆层迭代流程；TransHarness 则给出防基准过拟合的工程护栏（独立进化集 + 语义选择），两者共同回答"harness 进化如何不翻车"。
2. **[TASK Memory（2611.34762）](https://arxiv.org/abs/2611.34762) × [When Skills Fail to Compose（2611.34398）](https://arxiv.org/abs/2611.34398)** — 分别击中 local-first 记忆层与 Skill 架构的两个隐性失效模式：检索对了模型却不照用（memory-ignoring 最高 46%，靠引导向量 + 可编辑知识地址压到 ≤1.5%）；单技能都 ≥90% 但组合即崩（≤7.6%，必须把兼容性/保持/迁移纳入技能库评估）。对我们的启示：记忆层要管"用的时候"，技能库要管"组合的时候"，两者都有开源代码可复现。
